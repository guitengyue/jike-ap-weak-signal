# 原厂 AP 的实际部署经过

这次在集客原厂固件上增加了两个功能：由无线驱动拒绝弱信号接入，由 AP 上的后台程序剔除持续弱信号的终端。下面记的是现场实际做过的步骤。已经能在后台看到功能面板的用户，可以直接跳到[面板设置](#panel)。

<a id="prepare"></a>
## 1. 从 AC 找设备，登录 AP 的 Web 后台

先从 AC 读出每台 AP 的管理地址、型号、完整固件版本和在线状态，再登录选定 AP 自己的管理页。原厂页面可以查看终端信号和手动断开终端。“漫游信号阈值”用于多台 AP 之间的漫游判断，单独修改这一项不能实现两道门槛。

现场全程没有使用或开启 SSH。设备所有者授权试点后，使用 AP 的管理员账号建立 Web 会话。该固件的管理接口对输入参数校验有缺陷，现场借此在 AP 内临时执行系统命令，并用 `id` 核实权限。后续的小文件经这条通道送入 AP 暂存，校验后才使用。

> **只有原厂网页账号的读者，到这里就能判断自己能否复现。** 网页账号可以用于盘点设备。下一步写入文件需要 AP 系统权限；仓库没有发布触发缺陷的请求、远程安装器或可供原厂网页上传的固件包。如果你已经有设备管理员提供的命令行和传输通道，可以按[公开工具手册](shell-lab.md)做单机实验。

<a id="build"></a>
## 2. 在试点 AP 上备份配置，匹配驱动

先导出这台 AP 的配置，留在管理电脑上。然后做两项核对：

- **哪几个无线接口要应用策略？** 按实际广播的 Wi-Fi 名称、频段和接口类型，找出供手机和其他终端连接的接口。排除无线回程、上联和 SOS 救援接口。
- **补丁是否匹配这台设备？** 读取 AP 只读分区中的原厂无线模块 `umac.ko`，用完整 SHA-256 指纹与电脑上的固件样本比对。指定的 AX1800MI 和 AX5RM 7.1 构建共用同一份原件，N3000 的 7.2 和 8.0 各有自己的原件。

<details>
<summary>现场在已取得系统权限的 AP 上怎样核对</summary>

```sh
id
uname -r
sha256sum /rom/lib/modules/4.4.60/umac.ko
iw dev
ls /sys/class/net/br-lan/brif
```

这些命令由设备端执行。普通网页没有可粘贴这些命令的终端窗口。

</details>

在电脑上离线验证了补丁后，现场向 AP 发送小型重建程序。它以**本机的只读原件**生成新模块，并将输出指纹与电脑端的预期值比较。只有两者完全一致才进入试启动。原厂固件分区保留，整个过程无需重刷固件。

<a id="observe"></a>
## 3. 重启一台 AP，分别启用两项功能

试点先记录这次启动要使用的模块。重启时，启动钩子先消费试用标志，再把已校验的补丁临时挂载到无线模块的装载路径。这样即使试启动失败，下次启动也有回到原厂模块的路径。AX 试点经限时核验后才确认后续继续使用；N3000 的定制流程则在业务接口和后台程序通过健康检查后，才为下次启动重新设置标志。

**拒绝新接入。** 无线启动后，逐个业务接口设置 `min_asoc_rssi -75`。补丁检查本次关联或重新关联请求的实际信号；低于门槛才走拒接分支。现场同时核对装载模块的指纹、挂载和 `g_min_asoc_rssi` 的读回值。原厂驱动也可能接受并读回 `-75`，所以读回参数本身不足以证明 2.4/5 GHz 已执行拒接。

**剔除已连接终端。** 常驻程序约每 5 秒读取一次关联表。同一连接连续三次收到低于 −82 dBm 的新活动读数，断开前复查仍低，才请求驱动断开。对需要始终保留的固定设备，在驱动的接入判断和后台的剔除判断中分别配置同一 MAC 的豁免；原有的 Wi-Fi 认证仍然有效。

<a id="panel"></a>
## 4. 已经有面板，怎样设置和关闭？

现场把这两项设置接到了**每台 AP 自己的无线设置页**，沿用原有管理员登录。7.1、7.2 和 8.0 分别适配了管理前端或认证方式。这里说的面板随现场定制部署提供。

1. 登录目标 AP，进入 **无线网络（或无线设置）→ 基本设置 → 弱信号接入与剔除**。
2. 勾选启用。**拒绝接入阈值**填 `-75`，**已连接终端剔除阈值**填 `-82`，保存。
3. 等页面显示**运行中**。查看“已应用接口数 / 总数”，两者相等才表示本机启用的业务接口都已读回目标接入门槛。
4. 要停用时，取消勾选并保存。页面显示**已关闭**后，后台停止弱信号剔除，业务接口的准入参数恢复为原厂值 `-90`。若还要恢复原厂驱动，则需要解除启动加载、重启，并复核模块指纹。

## 5. 试点验收后，再逐台推广

现场先通过管理页关闭、重新启用策略，再做一次正常重启，核对两道门槛能否恢复。其余 AP 逐台处理：先在 AP 上核实模块、运行状态和各业务接口的读数，再回 AC 确认设备上线，然后继续下一台。

设备端还用受控输入跑了 ARM 判断指令。普通终端在 −76 dBm 进入状态码 34 的拒接分支，在 −75 dBm 通过信号检查；受保护的终端也实地重新关联并完成了认证。普通终端在覆盖边缘实际收到拒接响应的过程仍待用独立网卡抓包确认。[如何验证空口行为](verification.md)

公开仓库保留了驱动构建、前台剔除脚本和[一次启动实验](boot-trial.md)。实验的剔除脚本在按下 Ctrl+C 后退出，启动示例仅尝试装载一次。上面记录的常驻服务、网页安装通道和批量部署程序仅用于现场定制部署。
