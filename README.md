# 集客AP的弱信号剔除功能

让集客 AP 在两个时机按信号强度做决定：终端请求连接时判断是否允许接入，终端已经连上后判断是否需要断开。两道门槛分开设置，终端靠近覆盖边缘时可以保留已有连接。

| 时机 | 本项目使用的参考策略 | 边界行为 |
| --- | --- | --- |
| 关联或重新关联 | AP 收到的请求帧信号低于 **−75 dBm** 时，以 802.11 状态码 **34** 拒绝本次请求 | −76 拒绝；−75 及以上通过这项检查 |
| 已连接 | 同一连接连续出现 **3 个不同的、新鲜的**信号读数低于 **−82 dBm**，复查仍低时断开 | −83 可触发；−82 保留；休眠期间的旧读数不重复计数 |

例如，已连上的终端降到 −78 dBm 时可以继续使用；如果它在同样的位置断线再连，这次接入会被拒绝。数值以 **AP 接收终端信号**的一侧为准。原厂的“漫游信号阈值”另有用途；它会配合其他 AP 寻找更好的接入点。

## 从哪里开始

| 你的情况 | 从这里开始 |
| --- | --- |
| AP 的「无线网络 → 基本设置」里**已经有「弱信号接入与剔除」面板** | 这是已集成管理页的版本。直接在这台 AP 的面板里设置两道门槛、保存，等到显示「运行中」且已应用接口数等于总数即可。 |
| 第一次使用 GitHub 公开版，想看看哪些终端可能被踢 | [跟着入门教程走一遍](docs/getting-started.md)。先用电脑上传一个 Lua 文件，在 AP 上观察约 10 秒。这条路径不需要改驱动或重启。 |
| 已经能读到信号，还需要**在连接前拒绝**弱信号终端 | [从自己的原厂模块构建补丁](docs/getting-started.md#build)，然后按[一次启动试用及恢复](docs/boot-trial.md)只测试一台 AP。 |

公开版是命令行工具。使用前需要已有的 AP 管理员 shell 和文件传输通道。**如果目前只有 AC 或 AP 网页的登录账号**，先确认是否有厂商提供或管理员已配置的 shell；GitHub 的 ZIP 和构建出的 `.ko` 都不能上传到网页的「固件升级」栏。

## 适用固件

| 型号 | 固件构建 | 平台 |
| --- | --- | --- |
| AX1800MI、AX5RM | `7.1_2022032400` | 高通 IPQ60xx |
| N3000 | `7.2_2022111500` | 高通 IPQ50xx |
| N3000 | `8.0_2024061700` | 高通 IPQ50xx |

以上构建使用 32 位 ARM 和内核 `4.4.60`。构建工具还会核对原厂 `umac.ko` 的完整 SHA-256；同一型号换了固件，也需要重新确认模块。仓库提供补丁构建代码，原厂模块由使用者从自己设备的只读分区取得。

## 使用顺序

1. [下载文件、登录 AP、找到业务接口](docs/getting-started.md#prepare)。准备好电脑 PowerShell 和 AP 的 shell，先确认接口名和正在广播的 SSID。
2. [只观察，再决定是否剔除](docs/getting-started.md#observe)。先看 `readable_vaps` 和 `eligible`，确认选对接口后才加 `--apply`。剔除脚本前台运行，按 `Ctrl+C` 停止。
3. [可选：构建准入补丁](docs/getting-started.md#build)。对照机型、构建号和原件 SHA-256。需要保护固定设备时，在构建和剔除这两处分别配置它的 MAC。
4. [在一台 AP 试用，核对挂载、门槛和回退](docs/boot-trial.md)。一次启动试用只负责装载模块；确认后还要对目标接口设置准入门槛。下一次正常重启可恢复原厂模块。

## 已验证到哪一步

针对上述固件的设备定制版本，已做过真机重启、业务接口读回和本机 ARM 决策测试。公开构建器另用精确匹配的原厂模块做离线指令测试；公开示例没有替读者的设备安装或启用策略。实机使用的一键部署、AC 下发配置和各版本后台页面改动依赖现场管理环境，本文提供的是可单独使用的驱动构建、AP 本地执行和验收流程。

现场验收时，记录目标 BSSID、关联响应与 AP 侧读数。手机自行漫游到另一台 AP 也会让原 AP 的在线列表发生变化。[验证方法、边界样例与回滚检查](docs/verification.md)
