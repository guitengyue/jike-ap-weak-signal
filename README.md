# 集客AP的弱信号剔除功能

**原厂 AP 实装用的是 Web 管理接口，全程没有用 SSH。** 现场先在 AC 确认设备，再登录单台 AP 的 Web 后台。由于特定固件的管理接口存在参数校验缺陷，经过认证的会话可以取得临时 root 命令执行能力。现场通过这条通道暂存文件、校验并重建驱动，之后才安装本机守护进程和管理面板。

**第一次读请从[原厂 AP 实际部署记录](docs/getting-started.md)开始。** 文中按实操顺序说明了每一步做了什么、怎么核验，以及哪一步依赖现场的管理通道。只有原厂网页账号时，公开仓库无法独立完成整套安装；这里没有发布利用该缺陷的请求、Web 安装器或可直接上传的升级包。

## 两道门槛分别管什么

让集客 AP 在两个时机按信号强度做决定：终端请求连接时判断是否允许接入，终端已经连上后判断是否需要断开。两道门槛分开设置，终端靠近覆盖边缘时可以保留已有连接。

| 时机 | 本项目使用的参考策略 | 边界行为 |
| --- | --- | --- |
| 关联或重新关联 | AP 收到的请求帧信号低于 **−75 dBm** 时，以 802.11 状态码 **34** 拒绝本次请求 | −76 拒绝；−75 及以上通过这项检查 |
| 已连接 | 同一连接连续出现 **3 个不同的、新鲜的**信号读数低于 **−82 dBm**，复查仍低时断开 | −83 可触发；−82 保留；休眠期间的旧读数不重复计数 |

例如，已连上的终端降到 −78 dBm 时可以继续使用；如果它在同样的位置断线再连，这次接入会被拒绝。数值以 **AP 接收终端信号**的一侧为准。原厂的“漫游信号阈值”另有用途；它会配合其他 AP 寻找更好的接入点。

## 按你手里的设备选入口

| 你的情况 | 从这里开始 |
| --- | --- |
| AP 的「无线网络 → 基本设置」里**已经有「弱信号接入与剔除」面板** | 这是已集成管理页的版本。直接在这台 AP 的面板里设置两道门槛、保存，等到显示「运行中」且已应用接口数等于总数即可。 |
| 原厂 AP，目前只有 AC 或 AP 的网页账号 | [看实装经过和权限分界](docs/getting-started.md)。可以先核对型号、固件和当前终端；GitHub ZIP 和单个 `.ko` 都不能上传到网页的「固件升级」栏。 |
| **已经有**管理员 shell 和文件传输通道，希望自己复现实验 | [可选：已有 shell 的实验教程](docs/shell-lab.md)。先只观察，按需要试用剔除；需要拒绝新接入时再构建补丁，按[单次启动与恢复](docs/boot-trial.md)测试。 |

## 适用固件

| 型号 | 固件构建 | 平台 |
| --- | --- | --- |
| AX1800MI、AX5RM | `7.1_2022032400` | 高通 IPQ60xx |
| N3000 | `7.2_2022111500` | 高通 IPQ50xx |
| N3000 | `8.0_2024061700` | 高通 IPQ50xx |

以上构建使用 32 位 ARM 和内核 `4.4.60`。构建工具还会核对原厂 `umac.ko` 的完整 SHA-256；同一型号换了固件，也需要重新确认模块。仓库提供补丁构建代码，原厂模块由使用者从自己设备的只读分区取得。

## 公开的工具

- [终端剔除脚本](tools/rssi_kick.lua)在 AP 上运行，默认只观察，显式传入 `--apply` 才会断开终端。[接口选择和输出说明](docs/shell-lab.md#observe)
- [准入补丁构建器](tools/build_umac.py)在电脑上读取指定版本的原厂模块并生成新文件。[原件指纹和构建步骤](docs/shell-lab.md#build)
- [单次启动示例](docs/boot-trial.md)供已有管理员 shell 的测试 AP 使用，确认加载后仍需逐接口设置门槛。

## 已验证到哪一步

设备定制版本做过真机重启、业务接口阈值读回和本机 ARM 决策测试。公开构建器和前台 Lua 脚本另做了离线测试。现场由各台 AP 独立执行两道门槛，AC 用于设备发现和上线核验。

现场验收时，记录目标 BSSID、关联响应与 AP 侧读数。手机自行漫游到另一台 AP 也会让原 AP 的在线列表发生变化。[验证方法、边界样例与回滚检查](docs/verification.md)
