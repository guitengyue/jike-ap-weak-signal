# 集客AP的弱信号剔除功能

让集客 AP 在两个时机按信号强度做决定：终端请求连接时判断是否允许接入，终端已经连上后判断是否需要断开。两道门槛分开设置，终端靠近覆盖边缘时可以保留已有连接。

| 时机 | 本项目使用的参考策略 | 边界行为 |
| --- | --- | --- |
| 关联或重新关联 | AP 收到的请求帧信号低于 **−75 dBm** 时，以 802.11 状态码 **34** 拒绝本次请求 | −76 拒绝；−75 及以上通过这项检查 |
| 已连接 | 同一连接连续出现 **3 个不同的、新鲜的**信号读数低于 **−82 dBm**，复查仍低时断开 | −83 可触发；−82 保留；休眠期间的旧读数不重复计数 |

例如，已连上的终端降到 −78 dBm 时可以继续使用；如果它在同样的位置断线再连，这次接入会被拒绝。数值以 **AP 接收终端信号**的一侧为准。原厂的“漫游信号阈值”另有用途；它会配合其他 AP 寻找更好的接入点。

## 适用固件

| 型号 | 固件构建 | 平台 |
| --- | --- | --- |
| AX1800MI、AX5RM | `7.1_2022032400` | 高通 IPQ60xx |
| N3000 | `7.2_2022111500` | 高通 IPQ50xx |
| N3000 | `8.0_2024061700` | 高通 IPQ50xx |

以上构建使用 32 位 ARM 和内核 `4.4.60`。构建工具还会核对原厂 `umac.ko` 的完整 SHA-256；同一型号换了固件，也需要重新确认模块。仓库提供补丁构建代码，原厂模块由使用者从自己设备的只读分区取得。

## 先观察已连接终端

在已有管理员 shell 的 AP 上，用 `iw dev` 核对接口、SSID 和类型，选一个终端实际使用的业务接口。下文用 `ath0` 举例。每个无线频段和 SSID 对应的接口可能不同；救援接口和 Mesh 回程应单独保留。

```sh
# 在 AP 上执行。默认只观察一个采样窗口。
lua rssi_kick.lua --iface ath0 --once

# 确认选对接口后，显式启用自动剔除；前台运行，Ctrl+C 停止。
lua rssi_kick.lua --iface ath0 --threshold -82 --loop --apply
```

脚本使用固件自带的 `uci`、`iwinfo.qcawifi`、`nixio`、`iw` 和 `cfg80211tool`。这一部分可以先在原厂驱动上观察。接入前的拒绝由下一节的驱动补丁执行。[终端剔除脚本](tools/rssi_kick.lua)

## 构建接入补丁

1. 从目标 AP 复制 `/rom/lib/modules/4.4.60/umac.ko` 到电脑，保留原件，命名为 `umac.stock.ko`。
2. 在电脑的 Python 环境中安装依赖并生成新模块。补丁只作用于匹配的原厂输入。

```sh
python -m pip install keystone-engine==0.9.2
python tools/build_umac.py umac.stock.ko patched.ko
```

需要保护固定设备时，在构建命令加 `--exempt-mac <设备MAC>`，并在剔除脚本加 `--protect <同一设备MAC>`。尖括号表示需要替换的参数。两处分别保护新接入和已有连接；原有的 Wi-Fi 密码认证和访问控制仍由固件执行。[离线构建工具](tools/build_umac.py)

## 在一台 AP 上试用

先准备有线管理路径和设备原厂恢复手段，导出当前 AP 配置。无线模块已经被射频和其他内核模块引用，试用安排在设备启动时。目录中的示例仅用于一次受控重启，需经已有管理员 shell 安装。[单次启动试用与回退](docs/boot-trial.md)

确认这次启动实际使用了补丁模块后，才对选定业务接口设置和读回准入门槛：

```sh
cfg80211tool ath0 min_asoc_rssi -75
cfg80211tool ath0 g_min_asoc_rssi
```

对清单中每个目标接口分别执行。在这些构建上，原厂驱动也可能成功保存并回读这个参数，但会在 2.4/5 GHz 跳过相应判断，因此单独一条读回记录不足以验证拒接。恢复该接口原厂准入行为用 `cfg80211tool ath0 min_asoc_rssi -90`；已连接终端的剔除程序单独停止。

## 已验证到哪一步

针对上述固件的设备定制版本，已做过真机重启、业务接口读回和本机 ARM 决策测试。公开构建器另用精确匹配的原厂模块做离线指令测试；公开示例没有替读者的设备安装或启用策略。实机使用的一键部署、AC 下发配置和各版本后台页面改动依赖现场管理环境，本文提供的是可单独使用的驱动构建、AP 本地执行和验收流程。

现场验收时，记录目标 BSSID、关联响应与 AP 侧读数。手机自行漫游到另一台 AP 也会让原 AP 的在线列表发生变化。[验证方法、边界样例与回滚检查](docs/verification.md)
