# 验证弱信号接入与剔除

验收分两步。先确认策略已加载到指定的业务无线接口，再从空口观察终端的关联请求和 AP 的响应。接入测试从终端尚未关联时开始。剔除测试从已关联且持续发送上行流量的状态开始。

## 已验证的范围

| 机型 | 固件构建 |
| --- | --- |
| AX1800MI、AX5RM | `7.1_2022032400` |
| N3000 | `7.2_2022111500`、`8.0_2024061700` |

上述固件的设备定制版本已完成真机重启和业务接口阈值回读。仓库中的公开构建器使用这三种原厂模块分别生成了默认版本和单 MAC 豁免版本，离线检查了 ELF 结构及 62,880 组 ARM 收帧与关联判断用例。公开剔除脚本分别在 Lua 5.1 和 LuaJIT 2.1 上运行了相同的 36 个模拟场景。公开版尚未做真实空口测试。可用三种匹配的原厂模块复核驱动判断：

```sh
python -m pip install keystone-engine==0.9.2 pyelftools==0.33 unicorn==2.1.4
python tests/test_umac.py stock-ax.ko stock-n3000-7.2.ko stock-n3000-8.0.ko
```

在仓库根目录运行 `lua tests/test_kick.lua` 或 `luajit tests/test_kick.lua`，可用模拟的无线接口、信号和时钟复核剔除判断，无需连接 AP。

## 参考配置与边界

接入阈值取 **−75 dBm**，剔除阈值取 **−82 dBm**。数字越负，信号越弱。两个门槛之间的 7 dB 允许已经连上的终端继续使用网络，同时避免更弱的新连接。

| AP 端收到的有效读数 | 新关联或重新关联 | 已关联终端 |
| --- | --- | --- |
| −74 dBm | 继续原有关联流程 | 保留 |
| −75 dBm | 等于接入阈值，继续原有关联流程 | 保留 |
| −76 dBm | 拒绝本次请求 | 保留 |
| −82 dBm | 拒绝本次请求 | 等于剔除阈值，保留 |
| −83 dBm | 拒绝本次请求 | 连续 3 个不同的有效活动读数低于门槛，执行前复核仍低于门槛，才请求断开 |

接入判定读取 AP 收到本次关联帧的信号强度。剔除程序约每 5 秒检查一次关联表，并用活动时间识别新读数。休眠终端的同一条低读数重复出现时不会积累到三次。切换 BSSID、重新建立连接或信号回升后，应重新观察当前连接的样本。通过信号检查后，终端仍须通过原有认证和访问控制。

## 先做设备侧检查

1. 在一台有独立有线管理通道的测试 AP 上记录原厂构建、模块 SHA-256 和原始配置，准备可执行的回退流程。选定一个业务 BSS（一个具体的无线接口及其 BSSID），记录频段和信道。管理、救援和无线回程接口留在测试范围外。
2. 启用参考配置，等运行状态更新。逐接口核对接入阈值。对于带有下列查询命令的构建，可在已授权的本地管理终端查询。

   ```sh
   cfg80211tool "$TEST_VAP" g_min_asoc_rssi
   ```

   将 `TEST_VAP` 设为已核实的业务接口。启用时预期回读 `-75`。同时核对剔除程序已运行、读取的策略为 `-82`，并能取得该接口的关联表。单独的准入阈值回读只证明配置已到达接口。
3. 在强信号下让普通测试终端完整连接一次并收发数据，记录实际 BSSID。后续换频段、重启 AP 或重新下发无线配置时，再次检查实际 BSSID、阈值和剔除程序状态。

## 空口复现

使用一台支持监听模式的独立网卡，固定到目标 BSS 的信道。从强信号开始，逐步增加衰减，每一步保持稳定。优先使用射频衰减器或屏蔽环境。同步抓包主机和 AP 的时钟。抓包网卡报告的是它所在位置的 RSSI，手机显示的是下行信号。只有取得 **AP 对本次请求帧的接收值**，才能从实测断言恰好命中了某个 1 dB 的边界。

**接入。** 在每个衰减点让测试终端重新发起连接。在抓包中按发送终端、目标 BSSID 和时间配对 Association Request/Response 或 Reassociation Request/Response。保持在高于门槛时，应能完成原有关联和数据交换。低于门槛后，检查同一 BSSID 是否返回关联状态码 **34**，随后核对其关联表。条件允许时分别覆盖普通关联、重关联和两个频段。将策略关闭，在相同强度下重复，再开启复测，可以区分策略拒接与弱链路本身造成的丢帧。

**剔除。** 先在强信号下接入，保持少量连续上行流量，再逐步衰减到剔除阈值以下。同时记录 AP 端当前 BSS 的关联时长、活动时间、信号读数和剔除日志。连续两次低读数后恢复信号，检查连接得以保留。重新降低信号，出现三次新读数后，对齐剔除操作、空口解除关联或取消认证帧，以及该终端从原 BSS 关联表消失的时间。空口丢包或管理帧保护可能限制对原因码的观察，此时保留 AP 日志和抓包两种记录。最后恢复强信号并确认能重新连接。

**区分漫游。** 同一终端转入另一个 BSSID，只能说明它切换了接入点。要将切换归因于拒接，需找到收到本次关联请求的目标 BSSID 发出的拒绝响应。要归因于剔除，需在已经建立的连接上找到相符的 AP 端剔除日志及断开证据。802.11v 切换建议、DHCP 续租、Ping 短时中断可用于对齐上述事件的时间。只有未收到响应时，保留“未观察到响应”的结论。

**检查豁免。** 若使用设备豁免，以受保护的测试终端在同样的衰减条件下分别验证准入和已连接两条路径，再用普通测试终端重复测试。豁免终端仍受原有认证与访问控制约束。

## 关闭与回滚

先停止运行中的剔除脚本，再用 `cfg80211tool "$TEST_VAP" min_asoc_rssi -90` 恢复每个试用接口的原厂准入行为。确认驱动读回值为 `-90`，在同一衰减点再做一次接入、保持连接和恢复强信号的测试。

如需撤销驱动改动，应使用与本机版本匹配的回退流程，先解除下次启动时加载补丁的设置，再从只读原厂模块正常重启。重启后核对实际模块路径与只读副本的 SHA-256，确认覆盖挂载已消失、原厂无线业务恢复、管理通道可达。重新启用或更换固件前，先重新核实模块哈希与备份可用性。
